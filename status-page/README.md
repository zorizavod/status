# Принятая страница статуса

Реализация [ZOL-17982](https://paperclip.zolotenkov.ru/ZOL/issues/ZOL-17982), макет ZOL-17144, Plan ревизия 2, принят бордом запросом a27f52f2-0a59-42d3-b4b7-ce1f7fd94600. Тексты ZOL-17143, ревизия 2. Страница живет на GitHub Pages отдельно от основного сервера.

`npm ci`, `npm run check`, `npm test`, `npm run build`, `npm run test:e2e`.

Сборка требует полной истории Git (`fetch-depth: 0`). Генератор читает `history/summary.json` и коммиты `history/<slug>.yml`. Из YAML экспортируются только состояние, время начала и время замера. Секреты, адреса проверок и заголовки не попадают в браузер. История меняет состояние в момент зафиксированного замера; промежутки до первой проверки и после последнего сохраненного замера неизвестны. Процент без сбоев считается по пересечению наблюдавшихся интервалов с выбранным периодом; состояния `down` и `degraded` в доступное время не включаются. Никакая история для новых проверок не дописывается.

Все календарные границы и подписи используют Europe/Moscow. История «Все время» начинается в московскую полночь дня первой проверки. Данные публикуются после успешного прогона мониторинга, поэтому страница не зависит от лимита GitHub API посетителя.

Выкладкой управляет `.github/workflows/status-page.yml` через GitHub Pages Actions (`build_type: workflow`). Прежние `site.yml` и `setup.yml` публикуют старую страницу в ветку `gh-pages`; их нужно штатно отключить перед переключением Pages. Мониторинг (`uptime.yml`), сохранение замеров (`response-time.yml`), сводка и обновление шаблона остаются включенными. Отключенные рабочие процессы сохраняют это состояние при пересоздании файлов Upptime. После добавления проверок первый прогон `uptime.yml` создает их историю, следующий `summary.yml` обновляет сводку. Для возврата прежнего сайта: переключить Pages на ветку gh-pages и включить `site.yml`/`setup.yml`.

Модельные тесты проверяют вручную посчитанные проценты, неизвестные интервалы, московскую полночь, периоды и восстановление переходов состояния из Git. Сквозные тесты проверяют страницу с управляемыми данными: все периоды, новые проверки, загрузку, ошибку, повторный запрос, сбой, ссылки и подсказки на 360/390. Ожидания привязаны к состоянию страницы.
